# Offline Reinforcement Learning from Historical Operations Logs

Online exploration is often the wrong starting point for Industrial Engineering systems.

A production planner cannot deliberately create stockouts, a maintenance system cannot intentionally increase failure exposure, and a workforce scheduler cannot freely violate service requirements simply to collect exploratory data.

This benchmark therefore treats historical operational trajectories as a fixed dataset.

## Workflow

```text
historical behavior policy
        ↓
logged state/action/reward/next-state table
        ↓
offline policy learning
        ↓
off-policy evaluation from the same logs
        ↓
freeze policy
        ↓
held-out simulator test
```

The simulator is not available to the offline learner during fitting.

## Dataset

The benchmark uses logged finite-horizon inventory trajectories generated by a base-stock behavior policy with limited random action variation.

The variation creates some action coverage, but the dataset remains behavior-policy biased.

## Coverage diagnostics

The repository reports:

- fraction of nonterminal states observed;
- fraction of feasible state-action pairs observed;
- target-policy action support rate on visited states.

A target policy can look attractive under an extrapolating value function while choosing actions that were barely or never represented in the historical data. Coverage therefore matters.

## Behavior cloning

Behavior cloning reproduces the most common historical action at each observed state.

It is useful as a baseline because any offline RL method should justify deviating from a policy that is actually supported by the data.

## Pessimistic tabular fitted Q iteration

The Phase 1 benchmark uses count-based pessimism proportional to the inverse square root of the number of observations for a state-action pair.

This remains as a transparent finite-state reference.

## Conservative offline DQN

The neural offline learner uses a discrete CQL-style conservative objective:

```text
TD loss
+
alpha * (
    logsumexp_a Q(s,a)
    - Q(s, a_data)
)
```

Infeasible inventory actions are masked.

The conservative term pushes down values for actions that the network might otherwise overestimate relative to actions actually present in the logged dataset.

This compact implementation is described as **CQL-style** rather than as a reproduction of every Conservative Q-Learning variant or benchmark protocol.

## Fitted Q Evaluation

Before simulator testing, each frozen target policy is evaluated using Fitted Q Evaluation (FQE) on the logged transition table.

FQE iteratively applies the Bellman evaluation operator for the target policy using only observed transitions.

If the target action at a next state has poor dataset support, the estimate can be unreliable. For this reason FQE is always shown together with target-action support diagnostics.

## Simulator evaluation

Simulator evaluation is used only after policy learning and FQE are complete.

This separation represents the practical question:

> Can a policy be learned and screened from historical operating logs before any online deployment test?

The simulator result is used here because this is a synthetic benchmark and the ground truth is available. A real plant would not provide such a clean counterfactual test.

## Scope

The current benchmark is single-echelon inventory with discrete actions. Future extensions can use the same methodology for:

- dispatching and production scheduling logs;
- maintenance intervention histories;
- workforce allocation;
- energy dispatch;
- multi-echelon replenishment.

Offline RL is particularly relevant when exploration is costly, unsafe, or organizationally unacceptable.
