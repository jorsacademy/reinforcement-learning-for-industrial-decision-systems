# Offline RL for Industrial Process Control

Offline reinforcement-learning benchmark for industrial process control where **online exploration is not allowed**. Policies learn only from a fixed historical trajectory dataset generated by a bounded, safe behavior controller.

The repository compares:

- historical behavior policy,
- behavior cloning (BC),
- a discrete-action **CQL-style** conservative Q-learning policy.

The CQL implementation discretizes the continuous actuator range and applies a conservative log-sum-exp penalty to discourage optimistic values for unsupported actions. This is intentionally described as *CQL-style* rather than a full reproduction of every detail in the original CQL papers.

## Why offline RL matters in industry

In many manufacturing and process systems, unrestricted online trial-and-error is unacceptable because exploration can cause scrap, unstable operation, excessive energy use, equipment stress, or safety violations. Offline RL shifts the learning problem toward historical data quality, coverage, extrapolation error, and policy conservatism.

## Process model

The Gymnasium environment represents a stochastic, coupled three-state process. The controller manipulates one normalized actuator:

`u_t in [-1, 1]`

Observation:

`[x1, x2, x3, previous_action, normalized_time]`

The stage cost combines:

- quality deviation,
- actuator energy,
- control smoothness.

The reward is the negative total cost.

## Offline dataset

`data.py` generates fixed transitions using a bounded proportional behavior controller with small Gaussian exploration noise.

Each transition contains:

- observation,
- action,
- reward,
- next observation,
- terminal flag.

The generator also reports dataset diagnostics such as action range, action standard deviation, reward statistics, terminal fraction, and maximum state magnitude.

## Algorithms

### Behavior cloning

BC fits a neural policy directly to historical state-action pairs with mean-squared error. It is a useful low-variance baseline but does not explicitly optimize long-term return.

### CQL-style offline Q-learning

The actuator interval is discretized into action bins. The Q-network is trained with:

1. a Bellman error on historical transitions,
2. a conservative penalty of the form `logsumexp(Q(s, ·)) - Q(s, a_data)`.

The conservative term suppresses unsupported actions that might otherwise receive unrealistically high Q-values.

### IQL

Implicit Q-Learning is deliberately left as a research extension rather than being mislabeled by a simplified implementation. The current repository provides a defensible BC vs conservative-Q baseline that can later be extended to continuous-action IQL.

## Installation

Core environment, dataset utilities and tests:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e '.[test]'
```

Offline neural-policy training:

```bash
pip install -e '.[rl,test]'
```

## Generate historical data

```bash
python -m offline_process_control.data --episodes 300 --seed 10
```

This writes `data/offline_dataset.npz`.

## Train behavior cloning

```bash
python -m offline_process_control.train_offline \
  --dataset data/offline_dataset.npz \
  --algo bc \
  --epochs 500
```

## Train CQL-style policy

```bash
python -m offline_process_control.train_offline \
  --dataset data/offline_dataset.npz \
  --algo cql \
  --epochs 1500
```

## Evaluate on held-out seeds

```bash
python -m offline_process_control.evaluate \
  --episodes 50 \
  --bc-model artifacts/bc_policy.pt \
  --cql-model artifacts/cql_policy.pt
```

Evaluation reports:

- cumulative return,
- quality cost,
- energy cost,
- smoothness cost.

## Experimental design

A meaningful offline-RL study should separate data generation, training and evaluation seeds. Recommended experiments:

1. vary behavior-policy noise to change action coverage,
2. reduce dataset size and measure degradation,
3. train on nominal operating conditions and test process drift,
4. compare BC and CQL under narrow action support,
5. quantify out-of-distribution action frequency,
6. report confidence intervals over held-out seeds.

## Industrial-engineering interpretation

The central question is not simply whether offline RL beats a controller. It is whether historical plant data contain enough coverage to justify policy improvement without unsafe exploration. This connects reinforcement learning with process control, simulation, data quality, risk management and decision intelligence.
