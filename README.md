# Reinforcement Learning for Industrial Decision Systems

A research-oriented benchmark repository for studying **when reinforcement learning is useful in Industrial Engineering and Operations Research — and when classical optimization should remain the preferred method**.

This repository is intentionally not an algorithm gallery. Every RL method is attached to an explicit industrial decision problem, evaluated against a strong non-RL baseline, and reported with operational metrics rather than training reward alone.

## Core question

```text
industrial decision problem
        ↓
state / action / uncertainty / constraints
        ↓
strong OR or heuristic reference
        ↓
RL or offline-RL policy
        ↓
held-out common-random-number evaluation
        ↓
cost / service / tail risk / violations / resource use
```

The goal is not to demonstrate that RL always wins. A negative result — for example, exact dynamic programming or a simple operations policy outperforming RL — is a valid and useful engineering conclusion.

## Why this repository exists

Industrial engineers already have mature decision tools: linear and mixed-integer programming, constraint programming, dynamic programming, simulation, queueing models, heuristics, stochastic programming, and model predictive control. RL should therefore earn its place by solving a genuinely sequential problem under uncertainty where learning or fast repeated decisions provide value.

The first release focuses on three questions:

1. **Can RL approach an exact dynamic-programming policy on a stochastic inventory problem?**
2. **How should RL be evaluated when a real operational resource constraint — an overtime budget — must remain feasible?**
3. **What can be learned from historical trajectories when online exploration is not allowed?**

## Implemented benchmarks

### 1. Finite-horizon inventory control

State:

```text
(period, on-hand inventory)
```

Action:

```text
order quantity
```

Uncertainty:

```text
stochastic demand
```

Objective:

```text
minimize ordering + fixed-order + holding + lost-sales cost
```

Compared methods:

- exact finite-horizon dynamic programming;
- base-stock policy;
- tabular Q-learning.

Reported metrics:

- mean cost;
- p90 cost;
- fill rate;
- stockout-period rate.

Run:

```bash
python experiments/inventory_control.py
```

### 2. Constrained capacity allocation

A producer repeatedly selects production quantity under stochastic demand. Production above regular capacity consumes a finite **episode-wide overtime budget**.

State:

```text
(period, net inventory/backlog, overtime already used)
```

Action:

```text
production quantity
```

Hard constraint:

```text
cumulative overtime <= overtime budget
```

Compared methods:

- exact dynamic programming with overtime budget embedded in the state;
- myopic production policy;
- tabular Q-learning with an overtime shadow-price / Lagrangian reward term.

The environment enforces the hard overtime budget. The Lagrangian term is used as reward shaping; this implementation is **not** presented as a general-purpose constrained-policy-optimization algorithm.

Reported metrics:

- mean cost;
- p90 cost;
- average overtime;
- hard-budget violation rate;
- final backlog.

Run:

```bash
python experiments/constrained_capacity.py
```

### 3. Offline inventory learning

The learner receives a fixed logged dataset generated by a behavior policy. It does not interact with the simulator during fitting.

Compared methods:

- original behavior policy;
- tabular behavior cloning;
- pessimistic tabular fitted-Q iteration;
- exact DP as an information/model-advantaged reference.

The pessimistic fitted-Q implementation penalizes rare state-action pairs using visit counts. It is a transparent educational offline-RL baseline; it is **not** labeled as CQL or IQL.

Run:

```bash
python experiments/offline_inventory.py
```

### 4. Regime-switching inventory with DQN

This benchmark moves from tabular Q-learning to neural function approximation while retaining an exact reference.

State:

```text
(period, inventory, observed demand regime)
```

Action:

```text
discrete order quantity
```

Compared methods:

- exact regime-aware dynamic programming;
- regime-aware base-stock policy;
- DQN with replay, target network, and feasibility masking.

Run:

```bash
pip install -e ".[neural]"
python experiments/neural_inventory_dqn.py
```

### 5. Dynamic workforce allocation with PPO

Three work centers face stochastic period-by-period workloads. A limited pool of flex workers can be allocated across centers before each workload realization.

State:

```text
period + center backlogs + expected center workloads
```

Action:

```text
one feasible allocation of the flex-worker pool across 3 centers
```

Compared methods:

- no-flex policy;
- one-step expected-cost allocation baseline;
- PPO actor-critic.

Reported metrics:

- mean cost;
- p90 cost;
- average flex workers used;
- final backlog.

Run:

```bash
pip install -e ".[neural]"
python experiments/workforce_ppo.py
```

See [`docs/neural_rl_ie.md`](docs/neural_rl_ie.md) for the Phase 2 methodology and limitations.

### 6. Energy-aware production with SAC

This benchmark introduces a genuinely continuous operational decision.

State:

```text
period + net inventory/backlog + current energy price + demand forecast
```

Action:

```text
continuous production quantity
```

The environment includes stochastic demand, mean-reverting energy prices, convex energy consumption, holding cost, and backlog cost.

Compared methods:

- myopic economic dispatch;
- rolling-horizon grid MPC using expected demand and price forecasts;
- Soft Actor-Critic (SAC).

Reported metrics:

- mean cost;
- p90 cost;
- mean energy cost;
- final backlog;
- total production.

Run:

```bash
pip install -e ".[neural]"
python experiments/energy_production_sac.py
```

See [`docs/energy_aware_production.md`](docs/energy_aware_production.md) for formulation and limitations.

## Design principles

### Strong baselines first

An RL policy is compared with the strongest transparent baseline that is reasonable for the declared model. Exact DP is used where the state space is small enough.

### Operational constraints stay visible

A real constraint is not silently converted into one arbitrary reward coefficient. The capacity benchmark reports hard overtime-budget violations separately.

### Common evaluation randomness

Policies in a benchmark are evaluated using the same held-out seed range so comparisons are paired on the same stochastic demand trajectories.

### Training and evaluation are separate

Evaluation seeds are disjoint from training/data-generation seeds.

### No production claims from synthetic data

All current benchmarks are synthetic educational/research environments. Cost reductions are model outcomes, not claims of realized factory savings.

## What to learn next

The intended Industrial Engineering sequence is:

```text
MDP + Bellman equations
        ↓
exact dynamic programming
        ↓
tabular Q-learning
        ↓
DQN for larger discrete state spaces
        ↓
PPO for general sequential policies
        ↓
SAC for continuous operational decisions
        ↓
constrained / safe RL
        ↓
offline RL (BC → CQL / IQL)
        ↓
model-based and hybrid RL + OR
```

The roadmap deliberately puts **constraints, offline data, and OR baselines** ahead of exotic RL architectures because these issues dominate many real industrial deployments.

## Scope

This is an educational and research benchmark suite, not a production control system. A production deployment would require validated process models, calibrated costs, operational data governance, monitoring, fallback logic, safety review, and integration with the relevant planning/MES/ERP/control systems.
